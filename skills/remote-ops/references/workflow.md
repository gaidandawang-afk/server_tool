# 执行与恢复：按需执行的操作清单

模型决定目标、用例和下一步；下面固定机械操作的入口，不自动选例、分配资源或重跑实验。
已完成且仍有效的步骤不重复。安全边界以根 AGENTS.md 为准。

## 从请求到结果

| 步骤 | 模型需要留下的决定 | 确定性操作 / 完成证据 |
|---|---|---|
| 确定任务 | 目标提交/差异范围、验证问题、用户约束 | 干净本地分支；TASK.md 记录 profile 路径 |
| 选择用例 | 改动→风险→用例理由、覆盖缺口、必要变体 | INDEX→候选 TEST.md；不先读所有实现和历史 |
| 准备 | 当前资源、所选依赖、GPU 授权 | `server_tool.py --profile <p> check`；新鲜资源事实，精确提交 |
| 同步并提交 | 当前连接路径与显式传输选项 | `run-case.py ... --name <unique> --summary`；立即记录 run 名/返回的 run ID；S 自己运行完整脚本 |
| 观察 | 当前是否已有足够证据 | 短连接有界 wait；脚本自动 fetch 摘要并输出精简判定 |
| 解释结果 | 通过/失败/不完整、覆盖边界、下一步 | 对实际失败读相应日志；TASK.md 只更新结论、路径和待办 |

完整用例已负责启动、请求、注入和清理；不由模型重写这条内部执行链。
check 不代替用户授权，也不把历史空闲状态或旧 PASS 当成本次事实。

## 切换网络

- 实验室直连与 B 跳转到达同一 S 时，只显式调整 profile 的连接字段并核对服务器主机密钥；保留 task/source/artifact 根和 run 名。
- Paramiko 不读取 OpenSSH ProxyJump。跳转时使用已建立且仅监听本机的转发端口；不要把未知端点当作同一服务器。
- 连接路径与源码传输独立选择：设置 SOURCE_GIT_URL / TOOLS_GIT_URL 时先推送精确提交，由 S 拉取；不设置的部分使用上传。
- GitHub 准备失败不等于用例失败。确认旧 run 已终止且尚未启动测试后，可以显式换传输方式并使用新 run 名；不能修改旧 run 输入或悄悄换依赖。

## 中断后的操作

| 观察到的情况 | 下一步 |
|---|---|
| 提交连接断开，是否启动未知 | 先恢复连接并对原 run 名执行 status；无法查询就记 UNKNOWN，禁止直接重发 run |
| 原 run 正在运行，或已终止但未取结果 | `run-case.py ... --name <原名> --resume --summary --destination <新的本地证据目录>`；不再同步/启动，不因本地源码后来变化而替换原输入 |
| wait 超时/断线 | wait 的失败只说明观察未完成；用同一 run 恢复观察，不启动另一份 GPU 实验 |
| fetch 失败或本地目录是早期快照 | 选择新 destination 重取；不覆盖既有目录，不将 running 快照当最终结果 |
| 已取回完整终态 | 本地 `summarize-result.py <artifact目录>`；需要日志再用 logs 或完整 fetch 到另一个目录 |
| 准备失败 | 查 preparation.log 与 invocation；修传输/配置，不进入业务根因推断 |
| 实际用例失败 | 读取失败断言对应日志和代码，按需进入 debug-service；同一启动阻塞不反复试其他用例 |

## TASK.md 最小工作上下文

写在 `work/<profile>/<task>/TASK.md`，这是本次任务的简短恢复笔记，不是共享状态或新的执行协议。
仅需以下内容，自由增删不相关项：

- 目标与提交范围：问题、基线、目标；已观察的 hash 是证据，下一次运行仍重新核对 HEAD。
- profile 路径、连接方式、用户对本轮 GPU 的授权范围；不复制凭据、完整 profile 或私钥。
- 选例及理由/缺口；必要模型/拓扑变体和重复要求。
- run 名、最后已核验状态与时间、result/log/provenance 路径。未确认提交写 UNKNOWN。
- 下一步具体命令或要回答的问题；不要复制完整工具输出和已放弃的操作历史。

新 agent 优先读该笔记和一个相关 skill，再按引用展开；若用户未指明任务且存在多个候选，只询问能消除歧义的任务信息。
